# HTTP upstream connections — contract (engine ⇄ api ⇄ web)

Product goal: while creating a route, the admin picks a connection type. **SMPP** = host/port/user/pass
(exists). **HTTP API** = pick an adapter (e.g. "Aakash SMS", "Sparrow SMS"), paste the token (and any
other fields that adapter needs), done. Adapter specs: `docs/providers/nepal.md` and
`docs/providers/nepal-adapters.json` (researched; trust VERIFIED entries, treat LIKELY ones as
best-effort and say so in the UI).

## Schema (migration 007_http_connections.sql — already written, do not change it)
`upstream_connections.kind` ('SMPP'|'HTTP'), `adapter` (id), `http_credentials_enc` ('v1:' AES-GCM of a
JSON object of credential key → value, CONTRACTS §2 format), `http_settings` jsonb (non-secret
settings), `dlr_token` (random 32+ char url-safe secret, generated by the api on create, used in the
provider DLR callback URL). For HTTP rows host/port/system_id/password_enc are NULL.
`max_tps`, `enabled`, `upstream_rates`, `route_connections` priority/weight all apply unchanged.

## Adapter catalogue (engine is the single source of truth)
Engine `GET /internal/v1/adapters` (X-Internal-Token) →
```json
{ "adapters": [ {
  "id": "aakash_v3", "name": "Aakash SMS (v3)", "country": "NP", "website": "...", "docs_url": "...",
  "confidence": "VERIFIED|LIKELY",
  "credentials": [ { "key": "auth_token", "label": "Auth token", "secret": true, "required": true, "placeholder": "...", "help": "..." } ],
  "settings":    [ { "key": "base_url", "label": "API base URL", "type": "url|string|number|bool|select", "default": "https://sms.aakashsms.com", "options": null, "required": false, "help": "..." } ],
  "dlr_mode": "none|poll|callback", "supports_balance": true,
  "destination_countries": ["NP"],          // null = any
  "notes": "Returns HTTP 200 on errors; ..."
} ] }
```
Adapters to ship: `sparrow_v2`, `aakash_v3`, `aakash_v4`, `messengernepal`, `twozero`, `nestsms`,
`swift_smartsms`, `bulletsms`, `bitmoro` (from the research JSON) **plus `generic_http`**: a configurable
adapter for unlisted providers (settings: method GET/POST, url template, body type query/form/json,
params template as JSON object with placeholders `{to}` `{to_local}` `{to_e164}` `{text}` `{sender}`
`{message_id}` and any credential key like `{token}`; success rule: http status list + optional
JSON path equals / body regex; message id JSON path; recipient format). Credentials for generic_http:
free-form `token`, `username`, `password` (all optional).

## Engine internal API additions (api calls these)
- `GET  /internal/v1/adapters` — catalogue above.
- `POST /internal/v1/connections/:id/test` `{ "to": "98XXXXXXXX", "text": "..." }` → sends ONE real
  message through that connection outside billing/CDR; returns
  `{ "ok": bool, "provider_message_id": str|null, "http_status": n, "request": {method,url (secrets masked),body (secrets masked)}, "response_body": "<first 4KB>", "error": str|null, "duration_ms": n }`.
  For SMPP connections it may return `{ok:false, error:"test send is HTTP-only"}` or implement it — either is fine.
- `GET  /internal/v1/connections/:id/balance` → `{ "supported": bool, "balance": "string as provider reports"|null, "raw": "<first 1KB>", "error": str|null }`.
- `POST|GET /internal/v1/provider-dlr/:dlr_token` — the api forwards provider callbacks here verbatim:
  JSON `{ "method", "query": {...}, "headers": {...lowercased}, "body_base64": "..." }` → engine
  resolves the connection by dlr_token, lets that adapter parse it, updates messages; returns
  `{ "accepted": n }` (404 if token unknown).
- `GET /internal/v1/connections/status` — HTTP connections appear like SMPP ones but with
  `"kind": "HTTP"`, `"adapter": "aakash_v3"`, `state`: `READY` (last call ok or no calls yet),
  `ERROR` (last call failed: `last_error`, `last_error_at`), `DISABLED`; `last_success_at`;
  `sessions: []`; tps/inflight/queue/totals as for SMPP.

## Public callback URL (api)
`POST|GET /v1/provider-dlr/:dlr_token` — unauthenticated except the unguessable token; rate limited;
forwards to the engine as above and returns 200 `OK` (providers retry on non-2xx). The full URL shown
to admins is `${PUBLIC_API_BASE_URL}/v1/provider-dlr/<dlr_token>` (nginx already proxies /v1/).

## Engine send semantics for HTTP connections
- Dispatcher treats an HTTP connection like an SMPP one: same token bucket (max_tps), selection,
  priority/weight, failover. Concurrency per HTTP connection: setting `max_concurrency` (default 10).
- Destination formatting per adapter (Nepal providers want local 10-digit `98XXXXXXXX`: strip `977`).
  If an adapter's `destination_countries` excludes the destination → treat as permanent failure on
  that connection and fail over (never send).
- Whole message text is sent in one request (providers split themselves); our billing parts stay as
  computed by the pipeline.
- Outcomes: success → SUBMITTED with provider message id (or our id if none) stored in smsc_msg_ids;
  definite rejection (documented error codes / 4xx except 408/429) → fail over, then FAILED + refund;
  429/5xx/timeouts/network errors → retry with backoff on the same connection then fail over; an
  ambiguous outcome (timeout after the request was sent) must NOT be resent to another provider —
  follow the existing engine semantics for SMPP submit timeouts (UNKNOWN outcome, no refund).
  Aakash v3 returns 200 on errors (check `error === false`) and can partially fail per number.
- DLR: `none` adapters (Sparrow): message stays SUBMITTED with `dlr_stat = 'NODLR'`; no sweeper may
  fail/refund it; UI shows "Sent (provider gives no delivery report)". `poll` adapters: a poller
  checks status/report APIs on an interval (setting `dlr_poll_interval_s`, default 60) for messages
  SUBMITTED in the last 48h on that connection. `callback`: via provider-dlr endpoint. Map provider
  statuses to DELIVRD/UNDELIV/EXPIRED/REJECTD and reuse the existing DLR aggregation + client
  forwarding (webhooks / SMPP deliver_sm) path.
- Secrets never appear in logs, errors, test-send echoes (mask) or status output.
- Outbound requests: 10s timeout, keep-alive pooling, User-Agent `smsgw/1.0`. Do NOT apply the
  webhook private-IP guard to provider URLs (admins set them), but `generic_http` URLs must be http/https.

## Management API (api)
- `GET /api/connections/adapters` (admin) → proxies the engine catalogue (cache 60s).
- `POST /api/connections` / `PATCH /api/connections/:id` accept `kind: "HTTP"` with
  `{ adapter, credentials: {...}, settings: {...}, name, max_tps, enabled }`; validate against the
  catalogue (required credentials present, unknown keys rejected, setting types). Credentials are
  write-only: GET returns `credentials_set: ["auth_token", ...]` never values; PATCH merges (omitted
  key = unchanged, empty string = clear). Response includes `dlr_callback_url` when the adapter's
  dlr_mode is `callback`.
- `POST /api/routes/quick` connection rows also accept
  `{ "type": "HTTP", "adapter", "credentials", "settings"?, "name"?, "max_tps"?, "priority"?, "weight"?, "cost_micros"? }`.
- `POST /api/connections/:id/test` `{to, text}` and `GET /api/connections/:id/balance` (admin) proxy the engine.
- `GET /api/routes/:id/status` includes HTTP connections (kind, adapter, READY/ERROR state, last_error).
